# proj1 中文说明

这是 CS180 Project 1 的中文说明文档，主要介绍代码的实现逻辑，以及如何配置环境并运行 main notebook。

英文版说明见 README_EN.md。

## 项目目标

本项目实现的是经典的 Prokudin-Gorskii 三通道黑白底片颜色复原。原始输入图像是将蓝、绿、红三个通道上下堆叠在一起的一张灰度图，需要先拆分通道，再把绿色和红色通道对齐到蓝色通道，最后重新合成为彩色图像。

## 目录结构

- code/：主要实现代码和主 notebook
- code/colorize_skel.py：单尺度对齐的参考实现
- code/main.ipynb：主实验流程，包含读取、切片、对齐、可视化和保存
- test_images/：输入测试图像
- test_results/：输出结果保存目录
- CS180_fa2026_proj1_data/：课程提供的数据集
- web/：展示用静态页面

## 代码实现逻辑

### 1. 读取和归一化输入图像

main.ipynb 会从 test_images/ 中读取一张堆叠好的灰度图，并把像素值归一化到 0 到 1 之间，方便后续做相似度比较。

### 2. 拆分三通道

图像在垂直方向被平均切成三段，分别作为蓝通道、绿通道和红通道。代码里会先按总高度的三分之一切开，再得到 b、g、r 三张图。

### 3. 裁剪黑边

原始底片四周通常有黑边，直接参与匹配会干扰结果。代码会对每个通道裁掉四周大约 10% 的区域，只保留中间有效内容用于对齐。

### 4. 计算匹配分数

代码提供了两种相似度度量：

- L2：衡量两张图像的欧氏距离，越小越好。
- NCC：归一化互相关，越大越好。

这两种分数都只在裁剪后的有效区域上计算，避免边缘黑边影响搜索结果。

### 5. 单尺度对齐

align_single_scale 的做法是穷举搜索一个有限范围内的平移量。对每一组 dx 和 dy：

- 用 np.roll 平移目标通道
- 截掉边缘受环绕影响的区域
- 计算与参考通道的 L2 或 NCC 分数
- 记录当前最优的位移

最后返回最佳对齐后的通道，以及对应的 dx、dy 和分数。

### 6. 金字塔对齐

align_pyramid 用于更大位移或更高分辨率图像。思路是从粗到细逐层对齐：

- 先把图像缩小到更低分辨率
- 在低分辨率上先找到大致位移
- 把上一层得到的位移传给下一层，作为初始偏移
- 分辨率逐步提高，搜索范围逐步收窄

这样能比纯单尺度搜索更稳定，也更适合位移较大的图像。

### 7. 合成彩色图像

对齐完成后，把红、绿、蓝三个通道重新堆叠成三通道彩色图，再用 matplotlib 显示并保存到 test_results/。

## 如何配置并运行 main

### 1. 激活 Python 环境

如果你已经有名为 cv 的 conda 环境，可以先激活它：

conda activate cv

### 2. 检查依赖

如果环境里没有下面这些包，需要先安装：

- numpy
- opencv-python 或 opencv
- matplotlib
- jupyter

### 3. 打开 notebook

在 VS Code 中打开 code/main.ipynb，并选择上一步激活的 Python 内核。

### 4. 确认工作目录

当前 notebook 里的路径默认使用 test_images 和 test_results，因此最好从项目根目录打开 notebook，或者确保 notebook 的当前工作目录就是项目根目录。

如果你是从 code/ 目录作为工作目录运行，而图片路径找不到，可以把数据路径改成相对上一层目录的形式。

### 5. 选择要处理的图片

在 notebook 里修改 IDX 就可以切换不同输入图像。代码会根据 IDX 读取对应的图片，并把最终结果保存到 test_results/ 下。

### 6. 按顺序运行单元格

建议按 notebook 的顺序执行：

1. 读取图片

2. 切分 b、g、r 三个通道

3. 查看切片结果

4. 跑单尺度对齐，比较 L2 和 NCC

5. 跑金字塔对齐

6. 保存最终结果

## 输出结果

运行结束后，输出图像会保存到 test_results/ 目录。文件名通常会保留输入图像的原始名字，并附加 jpg 后缀。
